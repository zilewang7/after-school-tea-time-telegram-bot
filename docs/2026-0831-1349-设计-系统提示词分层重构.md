# 系统提示词分层重构设计

## 设计目标（用户视角）

群友与 bot 对话时：bot 知道今天的日期（能正确回答"今天几号"、理解"昨天/上周五"这类相对时间，搜索时效性内容时不再按训练截止时间猜年份）；使用有视觉能力的模型（gemini/gpt/claude 等）时，提示词里不再有一段"OCR 识别文字如何理解"的无关说明去污染上下文——那段话只在模型看不到图、真的会收到 OCR 兜底文本时才出现。对维护者：改 bot 人设/偏好只需编辑一个很小的 `system-prompt.md`，不会再碰坏消息格式协议那一大段"系统的一部分"。

## 现状问题

- `system-prompt.md`（volume 挂载，`SYSTEM_PROMPT_FILE` 指向）是单文件大杂烩：角色偏好（4 行）+ 消息格式协议（~30 行）+ 能力说明 + OCR 兜底说明 + 注意事项全在一起。
- 格式协议部分实际是 context-builder 输出格式的**对偶物**（`#N` 编号、`[replying to]` 标注、`<<EOF`、`[#N]` 前缀都是构建期代码生成的），改代码必须同步改提示词文件，却分离在 repo 外的挂载文件里，天然容易漂移。
- `getSystemPrompt()`（platform-factory.ts:123）启动后缓存一份，不感知模型能力：视觉模型也被灌 OCR 说明；且没有任何当前时间信息。

## 方案：三层拼装

新增 `src/ai/system-prompt/` 模块，`buildSystemPrompt(capabilities)` 按序拼三层：

### 1. 偏好设定（env 注入，可热编辑）

- 来源不变：`SYSTEM_PROMPT_FILE`（挂载的 `system-prompt.md`）优先，`SYSTEM_PROMPT` env 兜底；读一次缓存；`{{BOT_USER_NAME}}` / `{{BOT_NAME}}` 替换逻辑原样保留。
- **内容瘦身**：`system-prompt.md` 留"# 角色"段（身份、emoji、中文回复）+ 禁止复读那条（评审结论：复读禁令是这个 bot 的行为偏好、不是通用协议，归外部提示词）。这是唯一鼓励维护者随手改的部分，改完 restart 生效（与现状一致）。
- 测试实例天然统一：test 容器挂载整个工作树、`.env.test` 同样指向 `system-prompt.md`，与生产共用同一份文件（靠 `{{BOT_USER_NAME}}` 区分身份），静态段进代码后两实例更是同源，无需额外动作。

### 2. 动态注入（每次请求计算）

- `当前时间：YYYY/MM/DD HH:mm 周X（Asia/Shanghai）`——含时分（评审结论：动态拼装下 prompt cache 命中本来就近乎 0，聊天用量也小，不为缓存牺牲粒度）。时区取 `process.env.TZ`（compose 已设 `Asia/Shanghai`），用 `Intl.DateTimeFormat` 格式化。
- `当前模型：<model id>`（评审新增）——让模型知道自己是谁在跑，`buildSystemPrompt(model)` 直接收 model 参数，capabilities 在内部由 `getModelCapabilities(model)` 推导，调用方只传一个参数、不会传错。

### 3. 静态内置默认（repo 内代码，含条件段）

- 消息格式协议、能力与输出、注意事项三段移入 repo，作为 TS 模板字符串常量（`sections.ts`），与生成这些格式的 context-builder 同库同版本，改格式时同一个 commit 里改提示词。
  - 不用挂载 md 文件的原因：静态段本质是代码协议的说明书，走 push+restart（build.sh 本来就重新拉取构建）而不是热编辑，类型检查也能保证不会因路径/挂载问题变成空串。
- **条件段**：OCR 兜底说明（现文件 28-29 行"`[system] 图中文字（OCR…）`是机器识别…"）只在 `!capabilities.supportsImageInput` 时注入——与 context-builder 注入 OCR 文本的条件（context-builder.ts:421、:428）严格同源。视觉模型的提示词里这段完全消失。
  - 同理，格式段里 `failed / too large / not visible` 那半句对所有模型保留（任何模型都可能遇到媒体不可见）。

### 拼装顺序与形态

```
[偏好设定（角色）]

# 当前环境
- 当前时间：2026/08/31 13:49 周一（Asia/Shanghai）
- 当前模型：gpt-5.4

# 你收到的消息格式
…（静态；OCR 一条按能力开关）…

# 能力与输出
…

# 注意
…
```

## 兼容与风险

- **部署顺序**：新代码上线时若挂载的 `system-prompt.md` 还是旧全量版，会出现格式协议重复一遍（旧文件一份+内置一份），不致错但啰嗦——发布时同步替换挂载文件内容再 restart 即可（同一台机器同一份文件，一次改完）。
- prompt cache：时间到分钟意味着几乎每次请求提示词都不同——评审已确认可接受（本来命中就近乎 0，用量小）。
- 测试实例共用同一份内置静态段，偏好文件本就按实例挂载（`{{BOT_USER_NAME}}` 机制不变）。

## 验证

1. `pnpm exec tsc --noEmit`。
2. tsx 冒烟：分别以 `supportsImageInput: true/false` 打印拼装结果，确认 OCR 段有无、时间行格式、`{{VAR}}` 替换。
3. test 实例 @bot 各问一次"今天几号"（视觉/非视觉模型各一），并回归一条带图消息。
